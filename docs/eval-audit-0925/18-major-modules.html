18. Major Modules

⚠️ AT RISK

Depends on a fix or on how strict the evaluator is. · audited 2026-09-25 · origin/main @ 9881704

Three Majors are solid (framework, real-time, user management). Permissions is arguable. WCAG, added today, is likely to score 0. The sheet question is "Are all claimed Majors properly implemented?", so one weak Major turns this question into a "No", even if the total still reaches 14.

What the evaluator is asked

Are all claimed Major modules properly implemented and functional?

  • Ask the team to demonstrate it
  • Verify it's fully implemented and functional
  • Check it meets Major module complexity requirements
  • Only count working modules. Non-functional or incomplete modules = 0 points

Red flags

highWCAG 2.1 AA: claimed with no proof

  • The subject asks for "complete accessibility compliance (WCAG 2.1 AA) with screen reader support, keyboard navigation, and assistive technologies". That is a demo with a screen reader and Tab-only navigation.
  • Found: 86 aria- attributes, 47 focus-visible styles, labels on form fields, <html lang> set per locale. These are good.
  • Missing: no "skip to content" link, no prefers-reduced-motion handling, a second <main> inside the root <main> (routes/events/$eventId.tsx:65), no axe or Lighthouse test in e2e/, no accessibility document.
  • README says "Tested with Lighthouse/Axe", but the repository has no result.

mediumPermissions: three roles, and the users list is open

The subject lists "admin, user, guest, moderator, etc." as examples, so three roles is defensible. But "different actions based on role" is weakened by users.getUsers being available to every logged-in user (Q14). Make it admin-only and the argument is clean.
