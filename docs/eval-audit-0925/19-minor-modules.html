19. Minor Modules

⚠️ AT RISK

Depends on a fix or on how strict the evaluator is. · audited 2026-09-25 · origin/main @ 9881704

Six Minors are solid: ORM, 2FA, i18n, SSR, additional browsers, notifications. Advanced search is arguable because the event catalogue has no text search box, even though the backend already accepts a search field.

What the evaluator is asked

Are all claimed Minor modules properly implemented and functional?

  • Ask the team to demonstrate it
  • Verify it's fully implemented and functional
  • Verify module dependencies are met

Red flags

mediumSearch without a search box

getEventsQuerySchema (packages/schemas/src/events.ts:23–29) has search, and the repository filters on it (event-listings.repository.ts:23). The /events route (routes/events/index.tsx:14–22) only exposes sort, category and page. Text search exists only in "My tickets" and the admin table. Suggested fix: add q to validateSearch and loaderDeps, pass it as search, and add a debounced <Input> above the filters (~1 h).

high2FA was built by a member who left

dkolodze is not on the team, so one of the four must demo 2FA (enrol with an authenticator app, log out, log in, enter the code, use a backup code) and explain how it works (better-auth twoFactor plugin, /verify-2fa, two_factors table, lockout). The evaluator may also ask whether a module built by a former member counts. Have the answer ready: it is in the repository and the team maintains it (mde-krui made later fixes, see §6).

lowEdge not automated

The doc covers Edge, but msedge did not run here. If an evaluator asks "did you test Edge?", someone should have opened it once.
